# Apitor-WASD

Single-file Python CLI remote for Apitor robots (R, J, S, Q, X, Wheels) over Bluetooth LE via the `apitor-ble` library. The whole app is one module, `apitor_remote.py` (~3700 lines). There are **no tests, no CI, no packages, no lint/typecheck/format config** — do not look for `pytest`, `ruff`, `mypy`, or a `pyproject.toml`.

## Commands

- Install: `python3 -m venv .venv && .venv/bin/pip install -r requirements.txt` (Python 3.10+; only dependency: `apitor-ble>=0.3.0`)
- Run: `.venv/bin/python apitor_remote.py` — requires a real terminal (exits 2 if stdin is not a TTY)
- Without a robot: `.venv/bin/python apitor_remote.py --simulate` — prints BLE command frames to stdout instead of connecting (use this to verify changes)
- Run a program file: `.venv/bin/python apitor_remote.py --program examples/квадрат.txt` (`examples/square.txt` is the English version)
- Build the printable kids' manual: `docs/build.sh` (needs `pandoc`, `graphviz`, `calibre`; markdown + `docs/diagrams/*.dot` → `docs/img/*.svg` + `docs/instructions-{ru,en}.pdf`)
- Exit codes: `0` clean quit, `2` error (bad profile, unreadable program file, no TTY), `130` Ctrl+C

## Gotchas

- Key-state (reading real key press/release from `/dev/input/event*`) is always attempted on Linux and is the default hold behavior; it needs the `input` group (`sudo usermod -aG input "$USER"`, then re-log) or root, otherwise the app warns and falls back to auto-stop by `--hold-timeout`. `sudo` works but is not recommended: it creates root-owned state files in `~/.config/apitor-control/`. `--no-key-state` turns the tracking off entirely (no `/dev/input` access at all, no warning). `--key-state-device` restricts which devices are watched, and holding Shift boosts the speed to 12 in remote mode only (restored on release).
- State lives in `~/.config/apitor-control/`: `addresses.json` (one cached Bluetooth address per model), `config.json` (lang, timings, journal), `runs.log`. Program files and the `_draft.txt` autosave live in `programs/` next to the script (overridable with `--program-dir` or `program_dir` in config). Flag priority: CLI flag → `config.json` → default.
- With a cached address, `q` connects directly without scanning; `--no-cache` disables this. If the cached robot is off, the app falls back to scanning and updates the cache.
- Robot drive directions are unverified on hardware for Robot R — after connecting, press `y` (test drive) and use `--flip-left/--flip-right` or `--left-motor/--right-motor` if directions are wrong.
- `Ctrl+C` stops all motors and disconnects before exiting.
- `--tui` draws a full-screen dashboard on the alternate screen with raw ANSI codes — no external deps: a permanent banner (status line + `Tui._mode_banner`, the mode name and its keys, wrapped by `_wrap_words` over `BANNER_ROWS`), the log, the program row and, only while a prompt is open, the input bar (`Tui._prompt_line`). All output goes through `Remote._emit`/`_say` (tag-aware: `Tui.note(tag, text)`), prompts render in the bottom bar from `self.prompt` (`title`/`text` keys), the external `$EDITOR` pauses (leaves the alt screen) and resumes the TUI, and `SIGWINCH` triggers a redraw. Non-TUI output must stay byte-identical to the old plain prints.
- Program files are plain text: RU and EN words both accepted (`вперёд` = `forward`/`up`, `назад` = `back`/`down`, `right` also as `rght`), single-symbol shorthand shown in the editor row is also parsed (`↑` `↓` `←` `→` `‖` `✦` `●3` `»8`, e.g. `↑5 →2`), `#` comments, `e`/`ё` and case forgiven, `×`/`*`/`,` as separators.
- Timed steps (`Step.seconds`) are the macro format: a number with a unit — `вперёд 1.2с` / `1.2s` / `1.2сек` / `1.2sec` / `1.2 seconds` (both `с` and `s` parse in either UI language; the language only decides what is written) or a bare `1.2` — means "drive for 1.2 s" instead of "1.2 steps". Counts and seconds mix freely in one file; `скорость N` is the program header only before the first step, mid-file it is a `»N` step ("change speed from here"). Durations round to 3 decimals (1 ms) — `secs_text`/`STEP_PRECISION`; the run loop `_run_motion`/`_sleep_checked` sleep against an absolute deadline (`RUN_TICK = 0.02`) so long macros do not accumulate drift. `MIN_STEP_SECONDS = 0.05`, `MAX_STEP_SECONDS = 600`; blink/color/repeat/speed cannot take seconds.
- Macros: `Remote._toggle_recording` (`m`, stopped by `Esc` or a second `m`) drives `MacroRecorder` (in `apitor_remote.py` after `parse_program`), which is fed from `_on_move`/`_stop` (movement segments), `_set_led`/`_led_blink` (`_rec_event`) and `_apply_speed_if_moving` (boost splits a segment into `»12 … »6`). Pauses become `pause` steps (`MIN_ACTION = 0.05`, `MIN_WAIT = 0.1`; a trailing pause before the stop is dropped), speed changes while idle are emitted just before the next motion. The finished macro is loaded into the editor as the "last program" (`set_program(...)`, `program_name = None`, `_draft_loaded = True`), so `Enter`/`r`/`t`/`f`/`g`/`p`/`x` work on it unchanged; while recording, `p`/`Enter`/`r`/`t`/`x`/`f`/`g`/`i` are blocked with `идёт запись макроса — сначала Esc (стоп)` (`_handle_action` checks `self.recording`, and `_start_program_run` guards the editor's `Enter` too).
- Reverse runs: `Enter` executes the program everywhere (remote included), `Shift+Enter` runs it without pauses (`_shift_held()` = key-state Shift state, so it works only with key-state). `r`/`R` (`rev_back`/`rev_back_np`) drive the route back **backwards** (forward<->back and left<->right mirrored), `t`/`T` (`rev_front`/`rev_front_np`) for a robot turned around by hand (only left<->right). `reversed_steps(editor, mode, drop_pauses=...)` builds the program on the fly (`REVERSE_MIRROR` maps the kinds; count steps become seconds; the editor program is left untouched; repeat is forced to 1 because a second pass starts from a different heading). Colours and speeds are re-inserted before every segment that was driven with them forward (so `●c`/`»N` appear at other moments), blinks stay blinks, `pause` steps are kept unless dropped. `RunPlan` carries steps/speed/repeat/rev/drop_pauses from `_start_program_run` to `_run_worker`, which prints `реверс задним ходом` / `реверс передом (робот развёрнут)` / `без пауз` in the start line.
- Key map: `Enter` = `run` (executes; warns when the program is empty), `esc` = stop (and ends a macro recording), `r`/`R`/`t`/`T` = reverse runs, `y` = test drive (moved off `t`), `e`/`E` = external editor in program mode only (in the remote mode `e` is motor 3). `_to_latin_layout` maps the Russian layout for all of it (`к`->r, `е`->t, `н`->y).
- Program colour steps use `COLOR_BY_NUMBER`/`NUMBER_BY_COLOR` (0..8 ↔ `Color` enum): `цвет 8` is white and `Color.WHITE == 10`, so never pass the file number straight into `Color(...)`.
- `docs/` is the printable RU/EN kids' manual: `instructions-*.md` + `diagrams/*.dot` + `style.css`, built by `docs/build.sh` (pandoc → HTML → calibre `ebook-convert` PDF with `--paper-size a4`, `--page-breaks-before="//*[name()='h1']"` — one page per chapter — and footer numbers via `--pdf-footer-template`). Generated `img/*.svg` and the PDFs are committed; `docs/*.html` is gitignored. No emoji in the text (no font coverage in PDF): use the program symbols `↑ ↓ ← → ‖ ✦ ● »` and `★` instead.
