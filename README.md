# Apitor пульт — управление роботом с компьютера

Простой пульт для конструктора **Apitor Robot R** (и других Apitor: J, S, Q, X,
Wheels) с управлением одной клавишей — подтверждать нажатия Enter'ом не нужно.
Работает поверх библиотеки
[`apitor-ble`](https://github.com/kaxpur/apitor-ble) по Bluetooth LE.

Кроме ручного управления есть **режим программы** (как у игрушечного Big Trak):
набираете шаги в пульте, выполняете по Enter, а программы хранятся и читаются
как обычные текстовые файлы — см. «Режим программы». А ещё пульт умеет
**записывать макрос** («делай как я», клавиша `m`) и везти записанный маршрут
**обратно** — задним ходом (`r`) или передом, если робота развернули рукой
(`t`): см. «Обратный проезд».

```
[ok] подключено: Robot R (AA:BB:CC:DD:EE:FF)
[motor] вперёд — скорость 6
[motor] стоп (клавиша отпущена)
```

## Установка

Нужен только **Python 3.10+** и Bluetooth-адаптер с BLE: вся зависимость —
одна библиотека `apitor-ble`, и её поставит скрипт запуска.

**Самый простой способ.** Скачайте проект (ZIP с GitHub или `git clone`) и
щёлкните дважды по файлу `run.sh` (Linux) или `run.bat` (Windows): скрипт сам
создаст `.venv`, поставит `apitor-ble` (первый раз нужен интернет, это
15–30 секунд) и запустит пульт. Следующие запуски мгновенные — можно сделать
ярлык на рабочем столе.

Из терминала то же самое — просто `./run.sh`, а все флаги передаются пульту
как есть: `./run.sh --simulate`, `./run.sh --tui --lang en`,
`./run.sh --program examples/квадрат.txt`.

**Руками** (если хочется контролировать каждый шаг):

```bash
git clone https://github.com/XelorR/Apitor-WASD.git
cd Apitor-WASD
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt     # Windows: .venv\Scripts\pip install -r requirements.txt
```

Если клонировать репозиторий не хочется, достаточно одного файла `apitor_remote.py`
и библиотеки рядом с ним: `pip install apitor-ble`.

Проверить установку можно без робота — в режиме симуляции (кадры команд печатаются в консоль):

```bash
./run.sh --simulate
```

## Запуск

Короткий путь — `run.sh` / `run.bat` (см. «Установка»), он передаёт пульту
все флаги. Ниже — прямой запуск; везде `.venv/bin/python` — это Python из
виртуального окружения проекта (на Windows это `.venv\Scripts\python`).

```bash
.venv/bin/python apitor_remote.py
```

Полезные варианты:

```bash
.venv/bin/python apitor_remote.py --speed 9        # быстрее (1..12, по умолчанию 6)
.venv/bin/python apitor_remote.py --simulate       # без Bluetooth: показывать кадры
.venv/bin/python apitor_remote.py --tui            # полноэкранный интерфейс
.venv/bin/python apitor_remote.py --address AA:BB:CC:DD:EE:FF   # сразу по адресу
.venv/bin/python apitor_remote.py --latched        # сразу режим "фиксации"
.venv/bin/python apitor_remote.py --program examples/квадрат.txt   # программа при старте
.venv/bin/python apitor_remote.py --lang en        # английский интерфейс
```

## Горячие клавиши

| Клавиша(и) | Действие |
|---|---|
| `q` | подключиться (поиск робота или быстрый коннект по кэшу адреса) |
| `Shift+Q` | отключиться |
| `w` / `s` | вперёд / назад (стрелки `↑ ↓` тоже) |
| `a` / `d` | разворот на месте влево / вправо (стрелки `← →` тоже) |
| `пробел` или `Esc` | СТОП — мгновенно останавливает всё (на записи макроса `Esc` ещё и заканчивает запись) |
| `Enter` | выполнить программу: последний макрос (`m`) или загруженный файл (`g`, `--program`) |
| `Shift+Enter` | то же, но без пауз: маршрут проезжается без остановок (как это работает — «Про Shift» ниже) |
| `]` `[` или `+` `-` | скорость больше / меньше (1..12) |
| `Shift` (зажать) | буст: пока клавиша удерживается, скорость 12; отпустите — вернётся прежняя. Только в пульте и только при работающем key-state (см. ниже) |
| `1`…`8` | подсветка: красный, оранжевый, жёлтый, зелёный, голубой, синий, фиолетовый, белый |
| `0` | выключить подсветку |
| `b` / `B` | мигнуть подсветкой: короткая вспышка, цвет после неё остаётся прежним (в т. ч. «выключено»); в режиме программы маленькая `b` — шаг «мигнуть» |
| `v` / `V` | мотор 3 (аксессуар, если есть): вперёд / назад — включается/выключается повторным нажатием |
| `e` / `E` | править программу во внешнем редакторе (`$EDITOR`) — работает и в пульте, и в режиме программы (см. «Внешний редактор») |
| `r` / `R` | проехать маршрут обратно **задним ходом**: `r` — как записано, `R` (с Shift) — без пауз |
| `t` / `T` | то же, но робота развернули рукой на 180° — он едет обратно **передом**: `t` — как записано, `T` (с Shift) — без пауз |
| `y` | тест-поездка: вперёд, назад, влево, вправо |
| `i` | крутить моторы 1, 2, 3 по очереди (калибровка) |
| `k` / `l` | режим движения: **удержание** (k, стоп в момент отпускания) / **фиксация** (l) — это выбор, а не тумблер |
| `m` | записать макрос: делайте что угодно (езда, свет, паузы) — стоп по `Esc` или `n`, и записанное становится программой |
| `n` | закончить запись макроса (то же, что `Esc`; только во время записи) |
| `p` | режим программы: набор шагов (Enter — запуск) |
| `x` | очистить программу, не выходя из текущего режима |
| `f` / `g` | сохранить / загрузить программу файлом |
| `j` | журнал прогонов: включить/выключить (`runs.log`) |
| `h` или `?` | полная справка |
| `Ctrl+C` | выход (робот останавливается и отключается) |

Русская раскладка тоже работает: физические клавиши `й ц ф ы в` = `q w a s d`,
`Й` (Shift+Й) = `Shift+Q`.

Клавиша `x` очищает программу (и в пульте, и в режиме программы) и не трогает
движение: скорость меняется только на `]` `[` `+` `-`, стоп — только на
`пробеле`/`Esc`, чтобы случайное нажатие буквы не меняло скорость и не
останавливало робота. `Enter` в любом режиме выполняет программу (в пульте —
«последнюю»), `r`/`t` везут её обратно (раздел «Обратный проезд»), `e`/`E`
в любом режиме открывают внешний редактор, буквы `p`, `m`, `f`, `g`, `j`
отданы программе (раздел ниже), `y` — тест-поездка, `v`/`V` — мотор 3
(аксессуар), `i` — калибровка, а `x` — очистка программы.

### Про Shift

Shift — это сразу три вещи:

* **буст**: пока Shift зажат в пульте, скорость 12, после отпускания —
  прежняя (нужен key-state, см. «Стоп в момент отпускания» ниже);
* **Shift-варианты клавиш**: `Shift+Enter` — прогон программы без пауз,
  `R` и `T` — обратный проезд без пауз. Заглавную букву (`R`, `T`) терминал
  присылает сам, а `Shift+Enter` пульт узнаёт двумя способами: по key-state
  (физическая клавиша) и напрямую от терминала — при старте пульт спрашивает,
  умеет ли тот расширенные клавиши (kitty-протокол: kitty, foot, alacritty,
  wezterm, ghostty, свежий GNOME Terminal). Если умеет, key-state для
  `Shift+Enter` не нужен: клавиша работает сразу.

## Режимы движения

* **Удержание** (по умолчанию, клавиша `k`) — моторы крутятся, пока клавиша
  нажата: робот встаёт в момент отпускания (пульт читает реальное состояние
  клавиш — key-state, см. ниже). Если слежение за клавишами недоступно,
  работает запасной вариант: автоповтор ОС и авто-стоп через `--hold-timeout`
  секунд (по умолчанию 0.8 с). Короткое нажатие = небольшой толчок.
* **Фиксация** (клавиша `l`) — робот продолжает ехать после отпускания клавиши,
  пока не нажмёте `пробел` или другое направление. Удобно для дальних поездок,
  но требует присмотра.

`k` и `l` — не переключатель, а выбор режима: `k` всегда включает удержание,
`l` — фиксацию; повторные нажатия ничего не меняют.

### Стоп в момент отпускания (key-state)

Удержание работает «как в играх»: пульт читает **реальное состояние клавиш**,
поэтому движение прекращается в тот же момент, когда клавиша отпущена —
автоповтор и `--hold-timeout` не нужны. Слежение включается само при старте,
указывать ничего не нужно.

Платформа определяется автоматически:

* **Linux** — устройства `/dev/input/event*` (evdev). Обычно у локального
  пользователя доступ уже есть; если пульт пишет «key-state недоступен» —
  добавьте себя в группу `input` и войдите в систему заново:

  ```bash
  sudo usermod -aG input "$USER"
  # затем перелогиньтесь (или `newgrp input` в текущем терминале)
  ```

  Запускать пульт через `sudo` тоже сработает, но **не рекомендуется**: пульт
  получит лишние права root, а служебные файлы (кэш адреса, `__pycache__`)
  будут созданы от root и помешают обычным запускам. Один раз добавиться
  в группу — надёжнее и безопаснее.

  Читаются все клавиатуры сразу, новые (USB, Bluetooth) подхватываются на ходу.
* **Windows** — WinAPI (`GetAsyncKeyState`), права не нужны.
* **macOS** — пока не поддерживается.

Если слежение включить не удалось, пульт честно предупредит и продолжит в
обычном режиме: удержание с авто-стопом по `--hold-timeout`.

Особенности:

* Клавиши читаются **глобально** — даже когда окно пульта не в фокусе. Не
  печатайте `WASD` в других окнах, пока пульт запущен: робот поедет. Если
  клавиша зажата ещё до подключения (`q`), движение начнётся сразу после
  коннекта.
* Привязка к физическим клавишам: русская раскладка не мешает.
* Зажатый `Shift` — буст: скорость на время удержания становится 12, после
  отпускания возвращается прежняя. Работает только в пульте (в редакторе и во
  время прогона — нет) и только пока key-state доступен; `Shift+Q` при этом
  по-прежнему отключает робота. Если скорость при зажатом `Shift` поменять
  руками (`]`/`[`), победит ручное значение.
* Если удерживать две клавиши, активна последняя нажатая; при её отпускании
  робот возвращается к другой всё ещё зажатой клавише.
* `--hold-timeout` используется только запасным режимом (когда слежение не
  включилось).
* По умолчанию слушаются все клавиатуры системы. Опция
  `--key-state-device /dev/input/event7` ограничит слежение одним устройством
  (можно указать несколько раз) — полезно, если клавиатур несколько или для
  тестовых/синтетических источников событий.

## Полноэкранный интерфейс (`--tui`)

С флагом `--tui` пульт занимает весь экран (обычный экран терминала прячется и
возвращается при выходе, так что история команд остаётся на месте):

```
 Apitor Robot R · подключён · скор. 6 · удержание · key-state · свет: синий
 пульт: q — подключиться · Shift+Q — отключиться · w/a/s/d — ехать · Enter —
 пуск · пробел — стоп · m — макрос · p — программа · r/t — обратно · h — все…
 [robot] ищу робота (включён и не занят телефоном?)...
 [ok] подключено: Robot R (AA:BB:CC:DD:EE:FF)
 [motor] вперёд — скорость 6
   [sim] -> 55aa03060106
 [led] подсветка: синий
[prog] ↑5 · →2 · ‖ (3 шага · ~4.2 с · скор. 6)
```

* Сверху — **постоянный баннер**. Первая строка: робот, связь, скорость (`+` —
  идёт буст по Shift), режим движения, key-state, цвет подсветки, во время
  прогона — номер шага, а во время записи макроса — `запись N` (сколько
  действий уже записано). Вторая-третья строки — клавиши текущего режима
  («пульт:», «режим программы:», «прогон:», «запись макроса:»), так что
  видно и что происходит, и что можно нажать.
* В середине — лог событий: те же строки `[тег] …`, что и в обычном режиме, но
  с переносом по ширине окна.
* Снизу — строка программы (если она есть) и приглашение ввода, когда пульт
  что-то спрашивает (`f`/`g`): `[save] имя файла [программа-2026-01-01-1200.txt]:
  ▏`, `[load] номер: ▏`. Когда вопросов нет, строка не занимает место.
* Клавиши и поведение те же, что и без `--tui`; `h` печатает справку прямо
  в лог. Окно можно менять на ходу — интерфейс перерисуется под новый размер.
* Внешний редактор (`e`/`E` в режиме программы) забирает обычный экран себе и
  возвращает полноэкранный вид после выхода из редактора.
* Если терминал совсем старый и не понимает ANSI-последовательности,
  запускайте без `--tui` — вывод будет прежним, обычными строками.

## Режим программы

Программа — это набор шагов: поехать, повернуть, подождать, мигнуть, поменять
цвет. Набирается прямо в пульте, выполняется по `Enter`, сохраняется/загружается
файлами. Режим программы включает `p` — всегда и из любого места (и из пульта,
и из прогона): `p` никогда не возвращает в пульт, так что выйти случайно нельзя.
Обратно в пульт — только `Esc`; программа при этом остаётся в памяти.

```
[prog] ↑5 · →2 (2 шага · ~4.2 с · скор. 6)
[hint] w/a/s/d — шаги · 0..9 — число · c цвет · b мигнуть · пробел пауза · ...
```

Строка обновляется на каждое нажатие и всегда показывает текущую программу,
число шагов, оценку времени и скорость; `повтор N` добавляется, если повтор включён.
Каждый шаг показан одним значком: `↑` `↓` `←` `→` — движение, `‖` — пауза,
`✦` — мигнуть, `●` — цвет; число рядом — количество (`↑5`, `●3`).

### Набор программы

| Клавиши | Действие |
|---|---|
| `w` `s` `a` `d` (и стрелки) | добавить шаг: вперёд, назад, влево, вправо. Повторные нажатия подряд увеличивают число последнего шага: `wwwww` = «вперёд 5» |
| цифры `0`…`9` | число последнего шага: `w5` = «вперёд 5». Цифры, набранные подряд (быстрее секунды), складываются в одно число; `0` = 10, больше 99 отбрасывается. Если программу продолжить позже — цифра начинает новое число |
| `пробел` | шаг «пауза» (робот стоит на месте) |
| `b` | шаг «мигнуть»: светодиод мигает цветом последней команды `c` |
| `c` | шаг «цвет»: каждое нажатие — следующий цвет по кругу (красный → оранжевый → … → белый → выкл.). `c` и сразу цифра — точный цвет: `c3` — жёлтый, `c0` — выключить |
| `]` `[` (`+` `-`, `=` `_`) | скорость программы (1..12); цифры сразу после — точная скорость: `]12` = 12 |
| `*` | повтор программы по кругу: 1 → 2 → … → 99 → 1. `*5` — ровно 5 раз |
| `Backspace` | убрать последний шаг |
| `Enter` | запустить (с Shift — без пауз) |
| `r` / `R` / `t` / `T` | проехать маршрут обратно, не выходя из редактора: `r`/`t` — как записано, `R`/`T` — без пауз (то же, что из пульта) |
| `x` | очистить программу целиком |
| `e` / `E` | править программу во внешнем редакторе (`$EDITOR`/`$VISUAL`, иначе nvim/nano/vi) |
| `f` / `g` | сохранить / загрузить (файлом) |
| `Esc` | вернуться в пульт (программа остаётся в памяти) |

Клавиша `p` в режиме программы ничего не переключает: она лишь включает режим
программы (он уже включён), поэтому случайно выйти в пульт не получится.

### Макрос: пульт сам напишет программу (`m`)

Не хотите набирать программу вручную — покажите роботу, что делать. `m` в
пульте включает запись, дальше просто управляйте роботом: ездите, поворачивайте,
включайте свет, делайте паузы. `Esc` (или `n`) — и запись становится
обычной программой: её видно в строке редактора, она запускается `Enter`,
проезжается обратно `r`/`t`, правится `w/a/s/d` и `Backspace`, сохраняется `f`.

```
[rec] запись макроса: езда, свет, скорость — всё запишется, паузы станут ожиданием; Esc или n — стоп
[rec] ↑1.84с
[rec] ‖0.42с
[rec] →0.62с
[rec] макрос записан: 3 шага · 2.88 с — Enter — проехать, r/t — обратно, f — сохранить, p — править
```

* Записывается **всё, включая паузы**: стояли — в программе появится `‖0.42с`,
  ждать столько же. Именно паузы делают повтор похожим на оригинал.
* Время пишется **до миллисекунд** (`↑1.84с`), и повтор идёт по тем же временам:
  программа проигрывает вашу поездку с точностью до миллисекунд (плюс время
  самих команд Bluetooth). Суммарное время записи сразу видно в строке
  редактора (`~2.88 с`), а после прогона — сравнение плана и факта.
* `m` только **начинает** запись — остановить её можно `Esc` или `n` (клавиша
  добавлена специально: понятно и вслепую, никакого «тумблера»). Повторное
  `m` во время записи просто напомнит: «запись уже идёт — стоп: Esc или n».
* Пока идёт запись, `p`, `Enter`, `r`, `t`, `x`, `f`, `g` и калибровка не
  работают: сначала закончите запись («идёт запись макроса — сначала Esc
  или n (стоп)»). `Пробел` — просто стоп робота, запись при этом
  продолжается.
* Что чем записывается:

  | Действие | Шаг макроса |
  |---|---|
  | поехали и повернули | `↑1.2с`, `←0.7с` (отрезки с временем) |
  | постояли | `‖0.4с` (пауза) |
  | включили свет, мигнули | `●3`, `✦2` (как обычные шаги) |
  | сменили скорость (`]` `[`, буст на `Shift`) | `»8` — «отсюда ехать на скорости 8» |

* Подъём скорости бустом записывается как есть: `»12` на время зажатого
  `Shift` и `»6` — когда скорость вернулась. Следующее движение после этого
  едет уже с новой скоростью.
* Короткие толчки (< 0.05 с) и паузы (< 0.1 с) в макрос не попадают — это
  дребезг клавиш, а не поездка.
* Запись можно править как обычную программу, в том числе с секундами:
  `Backspace` убирает последний отрезок, а `w/a/s/d` добавляют новый шаг уже
  «в шагах» (числа к шагу с секундами не применяются — пульт предупредит).
* `x` очищает макрос так же, как программу, а `f` предлагает имя
  `макрос-2026-10-18-1010.txt` (у обычной программы — `программа-…`).
  В списке `g` макросы помечены: `макрос · 3 шага`.

### Обратный проезд (`r` / `R`, `t` / `T`)

Работает и из пульта, и из режима программы: `r` — проехать маршрут
обратно, `t` — то же для развёрнутого рукой робота, а `R` и `T` —
то же самое без пауз. Программа при этом не меняется.

Хочется вернуть робота в начало маршрута — не набирая вторую программу? Для
этого есть два способа, и оба проигрывают **тот же маршрут с конца**, сохраняя
длительность каждого действия и паузы:

* `r` — **задним ходом**: робот едет по маршруту в обратном порядке, но
  реверсится и «вперёд/назад», и «влево/вправо». Он остаётся развёрнутым так
  же, как стоял в конце маршрута, и пятится назад по своим следам.
* `t` — робота **развернули рукой на 180°** в конце маршрута. Тогда реверсится
  только «влево/вправо», а «вперёд/назад» остаётся как было: робот едет
  обратно передом.
* `R` и `T` (то же самое с зажатым Shift) — **без пауз**: маршрут проезжается
  без остановок, а всё остальное сохраняется. Как и `Shift+Enter`, такой
  вариант работает и без key-state: заглавную букву присылает сам терминал
  (см. «Про Shift»).

Скорости и свет ставятся заново **в точках смены**, а не там, где они стояли
в исходной программе. Идёт программа «скорость 6, вперёд, вправо, скорость
12, назад, вперёд» — это шаги «↑ → »12 ↓ ↑»; обратно робот поедет так:
«»12 ↓ ↑ »6 ← ↓» — сначала со скоростью конца маршрута (участок, который
ехали на 12, и обратно едем на 12), а на точке перелома, где в оригинале
задавали 12, включается 6 и держится до конца. Цвет — так же: перед каждым
отрезком стоит ровно тот свет, при котором этот отрезок проезжали вперёд,
и переключается он в тот момент, когда до отрезка доезжаешь. Участки,
которые ехали «при том, что горело» (цвет в программе не задавали), в
обратную сторону получают цвет, горевший до прогона.

* Шаги с числом («вперёд 5») превращаются в отрезки со временем
  («назад 3с»): важно проехать столько же секунд, а не столько же «шагов».
* Обратный проезд выполняется **один раз** (повтор `rN` не учитывается:
  после первого проезда робот стоит в начале маршрута и смотрит в другую
  сторону — второй раз тот же реверс уже не сработает).
* Сама программа не меняется: реверс строится на лету, так что после него
  `Enter` снова везёт вперёд, а `p` показывает исходные шаги.
* Цвета впереди: если робот ехал с включённым синим, обратно этот участок
  он проедет тоже с синим — а значит, `●3` появится в другой момент, не там,
  где он стоял в исходной записи: ровно там, где в обратном маршруте
  начинается «синий» отрезок (это видно в логе прогона).
* Участки без цвета: если в программе цвет не задавали, обратно включается
  цвет, горевший до прогона, — как и вперёд, когда участок ехали «при том,
  что горело».

### Внешний редактор (`e` / `E`)

`e` (или `Shift+E`) открывает текущую программу в редакторе — **в любом
режиме**: и из пульта, и из режима программы. В пульте после закрытия
редактора пульт остаётся пультом: `Enter` сразу везёт обновлённую программу.
Сначала берётся `$EDITOR`,
затем `$VISUAL` (можно с аргументами: `EDITOR="nvim -u NONE"`), а если они не
заданы — `nvim`, затем `nano`, затем `vi` (в Windows — `edit`, затем `notepad`).
Пока редактор открыт, горячие клавиши пульта выключены: работают только клавиши
самого редактора (в том числе `Esc`). Чтобы вернуться в пульт, сначала закройте
редактор, потом нажмите `Esc`. После закрытия пульт перечитывает программу; если
в файле ошибки, он покажет их и оставит прежнюю программу нетронутой. Во время записи
макроса редактор не открывается: сначала закончите запись (`Esc` или `n`).

### Запуск

`Enter` — и робот поехал. Что можно во время прогона:

* `пробел` — пауза / продолжить: моторы останавливаются, время шага не тратится;
* `Esc` — прервать и вернуться в пульт (программа цела: `p` — и правьте/запускайте снова);
* `p` — прервать и перейти в режим программы (правка и повторный запуск);
* светодиод подсказывает состояние: зелёная вспышка на старте, две зелёные —
  финиш, красная — прерывание. По завершении возвращается цвет, который был
  до запуска.

По окончании пульт сам возвращается в обычный режим и печатает отчёт
(`готово: N шагов за X с (план Y с)`, до сотых), а в подсказке предлагает
`Enter` (ещё раз), `r`/`t` (обратно) и `p` (редактор). `Enter` в пульте
запускает **последнюю** программу — выполненную, загруженную или записанную
последней; если программы ещё нет, он подскажет, что делать (`m` или `p`).
Если программа загружена файлом (`g` или `--program`), `Enter` запускает
именно её; если последним был макрос (`m`) — `Enter` проезжает макрос.

### Файлы программ

Программы — обычные текстовые файлы в папке `programs/` рядом со скриптом
(папка меняется флагом `--program-dir`). Их можно писать руками, читать и хранить
в git вместе с репозиторием:

```
# квадрат: четыре стороны и мигнуть в конце
скорость 5
повтор 4
вперёд 4
вправо 2
мигнуть 2
```

А так выглядит макрос, записанный клавишей `m`: вместо числа шагов у действий
стоят **секунды**, а смена скорости попадает в то место, где она случилась:

```
# макрос: подъехали, подождали, повернули, мигнули
скорость 6
вперёд 1.84с
пауза 0.42с
скорость 12
вправо 0.62с
мигнуть 2
цвет 3
```

Оба вида можно смешивать в одном файле: `вперёд 5` — пять «шагов», `вперёд 0.9с`
— ровно 0.9 секунды.

Файлы из старой папки `~/.config/apitor-control/programs/` просто перенесите
в новую — имена не меняются.

* Язык файла не важен — пульт всегда понимает и русские, и английские слова:
  `вперёд` = `forward` = `up`, `назад` = `back` = `down`, `влево`/`вправо` =
  `left`/`right` (`right` прощается и как `rght`), `пауза` = `pause`/`wait`,
  `цвет` = `color`/`colour`, `мигнуть` = `blink`, `повтор` = `repeat`,
  `скорость` = `speed`.
* Секунды — число с единицей: `вперёд 1.2с`, `вперёд 1.2s` (латинская `s`),
  `1.2сек`, `1.2sec`, `1.2секунды`, `1.2 seconds`. Обе буквы (`с` и `s`)
  понимаются в любом интерфейсе; язык влияет только на то, как пульт **пишет**
  файл: по-русски `↑1.2с`, по-английски `↑1.2s`. Точность — до миллисекунд
  (`1.234с`); короткие, но настоящие движения можно задать от 0.05 с.
* Строка `скорость 8` (`speed 8`) в начале файла — шапка программы; та же
  строка в середине — шаг «с этого места ехать на скорости 8» (так пишется
  буст или смена скорости в макросе; в строке редактора — `»8`).
* Можно и значками, как в строке редактора: `↑` = `вперёд`, `↓` = `назад`,
  `←`/`→` = `влево`/`вправо`, `‖` = `пауза`, `✦` = `мигнуть`, `●` = `цвет`,
  `»` = `скорость` — `↑5 · →2 · ●3` и `вперёд 5 · вправо 2 · цвет 3` — одна и
  та же программа, а `↑1.2с` значит «вперёд 1.2 секунды».
* `цвет 8` — белый (`10` в самом протоколе робота), `цвет 0` — выключить;
  `цвет 1`…`цвет 7` — красный, оранжевый, жёлтый, зелёный, голубой, синий,
  фиолетовый — те же цвета, что на клавишах `1`…`8`.
* Прощаются регистр, `е`/`ё`, лишние знаки: `вперёд ×5`, `вперёд x5` и `вперёд*5`
  — одно и то же; команды разделяются пробелами, запятыми или строками.
* `#` — комментарий до конца строки.
* Сохраняется файл на языке текущего интерфейса, читается — всегда на обоих.
* `f` спрашивает имя (по умолчанию `программа-2026-10-17-2130.txt` или имя
  последнего файла); если имя занято — попросит подтверждение (`y` — перезаписать).
* `g` показывает нумерованный список (до 12 файлов): цифра + `Enter` — загрузить,
  `Esc` — отмена. Без сохранённых программ и при пустой программе пульт честно
  предупредит, а не промолчит.
* Черновик: набранная программа сама сохраняется в `_draft.txt` в папке программ
  при выходе и подхватывается при следующем входе в редактор — случайно набранное
  не пропадёт.

Готовые примеры лежат в `examples/`. Их можно запустить сразу
(`--program examples/квадрат.txt`) или скопировать в папку программ и загружать
клавишей `g`; `examples/square.txt` — та же программа на английском.

### Единицы времени

«Вперёд 3» — это 3 × `--step-time`, поворот — × `--turn-time`, пауза —
× `--pause-time`, а одно мигание — 2 × `--blink-time`. По умолчанию
0.6 / 0.6 / 1.0 / 0.25 с. Подгоняйте под покрытие и заряд: оценка времени всей
программы сразу видна в строке редактора (`~X с`).

Число с единицей (`вперёд 1.2с`, `1.2s`, `1.2сек`) шагами не считается — это
ровно 1.2 секунды, так записывает макрос. Такие шаги не зависят от
`--step-time` и играются с точностью до миллисекунд.

### Настройки и журнал

Настройки хранятся в `~/.config/apitor-control/config.json` и создаются сами
(например, выбранный `--lang` запоминается). Приоритет: флаг → config → умолчание.

| Ключ | Значение |
|---|---|
| `lang` | язык интерфейса: `ru` или `en` |
| `step_time`, `turn_time`, `pause_time`, `blink_time` | единицы времени, с |
| `max_steps` | лимит команд в программе (0 — без лимита) |
| `journal` | `true` — вести журнал прогонов |
| `autosave` | `true` — хранить черновик между запусками |
| `program_dir` | папка файлов программ |

`--max-steps N` ограничивает длину программы: новый шаг сверх лимита пульт
не примет (увеличить последний шаг можно), а слишком длинный файл откажется
загружать. Удобно для соревнований на самую короткую программу (по умолчанию
лимита нет).

Журнал прогонов выключен по умолчанию; включается флагом `--log` или клавишей
`j` в пульте. Пишется в `~/.config/apitor-control/runs.log`:

```
2026-10-17 21:30:05 · квадрат.txt · 3 шага · план 18.43 с · факт 18.71 с · готово
```

## Калибровка под вашу сборку

Для Robot R в библиотеке заданы направления из официального приложения, но они
не проверены на реальном железе (в отличие от Robot J). Проверьте: подключитесь
(`q`) и нажмите `y` — робот поедет вперёд/назад/влево/вправо, и будет видно,
верны ли направления.

Если что-то не так, задайте при запуске:

```bash
# колесо крутится назад там, где должно вперёд:
.venv/bin/python apitor_remote.py --flip-left
.venv/bin/python apitor_remote.py --flip-right

# колёса подключены наоборот (робот едет наоборот или крутится вместо прямо):
.venv/bin/python apitor_remote.py --left-motor 2 --right-motor 1
```

Робот едет назад вместо вперёд — попробуйте `--flip-left --flip-right` (оба колеса).
Клавиша `i` поможет понять, какой порт крутит какое колесо.

## Инструкция для детей (`docs/`)

В `docs/` лежит «Большая инструкция для юных пилотов» — печатная книжка для
детей 6–15 лет: подключение, поездки, первые программы, испытания,
словарик и шпаргалка. Русская и английская версии собираются из общих
исходников:

* `docs/instructions-ru.md`, `docs/instructions-en.md` — текст;
* `docs/diagrams/*.dot` — схемы (graphviz), `docs/style.css` — оформление;
* `docs/pageref.py` — подставляет номера страниц в ссылки «см. раздел 5,
  стр. 6» (метки `{{page:N}}` в тексте);
* `docs/instructions-ru.pdf`, `docs/instructions-en.pdf` — готовые PDF
  (A4, номера страниц, каждая глава с новой страницы, содержание с номерами).

Пересобрать всё (нужны `pandoc`, `graphviz`, `calibre` и `pdftotext` из
poppler; на Debian/Ubuntu — `sudo apt install pandoc graphviz calibre
poppler-utils`):

```bash
docs/build.sh          # схемы, HTML и PDF для обоих языков
docs/build.sh ru       # только русская версия
```

Подробности и правила правки схем — в `docs/README.md`.

## Все параметры запуска

| Параметр | Назначение |
|---|---|
| `--product r` | модель: `r`, `j`, `s`, `q`, `x`, `w` (по умолчанию `r`) |
| `--speed 6` | начальная скорость 1..12 |
| `--hold-timeout 0.8` | авто-стоп через N секунд после отпускания — запасной режим, когда key-state недоступен |
| `--key-state-device ПУТЬ` | следить за клавишами только с указанного устройства (можно несколько; по умолчанию все клавиатуры) |
| `--no-key-state` | не следить за реальными клавишами вовсе: без /dev/input, без предупреждений — обычное удержание с авто-стопом по `--hold-timeout` |
| `--latched` | стартовать в режиме фиксации |
| `--address AA:BB:...` | подключаться сразу к известному адресу |
| `--scan-timeout 15` | сколько секунд искать робота при подключении |
| `--simulate` | не использовать Bluetooth, печатать кадры (проверка клавиш) |
| `--tui` | полноэкранный интерфейс: постоянный баннер сверху (состояние и клавиши режима), лог событий, строка программы |
| `--no-cache` | не запоминать адрес робота между запусками |
| `--left-motor` / `--right-motor` | номера моторов колёс (1..3) |
| `--flip-left` / `--flip-right` | развернуть соответствующее колесо |
| `--lang ru` / `--lang en` | язык интерфейса (выбор запоминается в config.json) |
| `--program ФАЙЛ` | загрузить программу при запуске (`Enter` — запуск, `p` — редактор) |
| `--program-dir ПАПКА` | папка файлов программ (по умолчанию `programs/` рядом со скриптом) |
| `--step-time` `--turn-time` `--pause-time` `--blink-time` | единицы времени программы, с (0.6 / 0.6 / 1.0 / 0.25) |
| `--max-steps N` | лимит команд в программе, 0 — без лимита |
| `--log` / `--no-log` | журнал прогонов `runs.log` (по умолчанию выключен) |
| `--verbose` | подробный журнал: кадры протокола, сканирование |

Адрес удачного подключения запоминается в `~/.config/apitor-control/addresses.json`,
поэтому повторные `q` в следующих запусках подключаются за секунду, без скана
(один адрес на модель; если роботов несколько — см. раздел ниже).

## Несколько роботов одной модели

Кэш хранит **один адрес на модель**, а `q` с непустым кэшем подключается напрямую
к запомненному роботу, без сканирования. Поэтому можно закрепить за компьютерами
разных роботов:

1. Включите **только нужного** робота, запустите пульт и нажмите `q` — его адрес
   попадёт в кэш этого компьютера.
2. Выключите его и повторите то же на другом компьютере с другим роботом.

Дальше, даже если включены оба робота, каждый компьютер по `q` подключается
к своему — коннект по кэшу в эфир не смотрит.

Важные нюансы:

* Первый `q` с пустым кэшем подключается к тому роботу, чьё объявление первым
  попалось в эфире. Если оба включены — это лотерея: чтобы закрепить конкретного,
  включайте его одного (шаг 1) или подключайтесь к адресу через `--address`.
* Если кэшированный робот выключен, `q` найдёт другого: пульт предупредит, что
  робот не из кэша, и обновит кэш. Подключится всё равно — чтобы `q` срабатывал
  сразу и надёжно. Вернуть «своего»: включите только его и снова нажмите `q`
  (или используйте `--address`).

## Если что-то не работает

* **"робот не найден"** — робот включён? Не подключён ли он к телефону
  (одновременно можно только к одному устройству)? Аккумулятор заряжен?
* **Подсветка не видна снаружи** — LED есть на самом блоке управления,
  смотрите на него, а не на колёса.
* **Не подключается с компьютера без Bluetooth** — нужен настоящий BLE-адаптер;
  в виртуальных машинах и WSL2 Bluetooth обычно недоступен (пробрасывайте USB).
* **Linux: сканирование падает с `No discovery started`** — встречается на новых
  BlueZ (например, 5.87), если сканировать с фильтром по service UUID. Этот
  пульт так не делает: сканирует без фильтра и сам ищет робота по имени.
* **Linux: key-state не включился, «нет доступа к /dev/input/event*»** —
  пользователь не входит в группу `input`. Добавьте себя:
  `sudo usermod -aG input "$USER"` и перезайдите в систему (или `newgrp input`
  в текущем терминале). Пока доступа нет, пульт работает в запасном режиме
  (авто-стоп по `--hold-timeout`) — подробнее в разделе
  «Стоп в момент отпускания (key-state)». Запуск через `sudo` тоже сработает,
  но не рекомендуется: файлы состояния достанутся root.
* **Windows: окно консоли "замерло"** — вы, вероятно, выделили текст мышью
  в режиме быстрого выделения. Нажмите `Esc` и запустите пульт заново
  (или отключите "Быстрое выделение" в свойствах окна консоли).
* **`--tui`: экран в мусоре или ничего не видно** — терминал не понимает
  ANSI-последовательности (бывает в старых консолях, `TERM=dumb`, части
  эмуляторов). Запустите без `--tui`; `Esc`/`Ctrl+C`/`q`+`Shift+Q` работают
  как обычно, а выход возвращает терминал в прежний вид.

## Файлы

* `apitor_remote.py` — сам пульт (один файл, зависимость только `apitor-ble`).
* `requirements.txt` — зависимости для установки.
* `examples/` — примеры программ («квадрат» на русском и английском).
* `docs/` — печатная инструкция для детей (RU+EN, markdown → PDF,
  собирается `docs/build.sh`; там же схемы `.dot` и готовые PDF).
* `.venv/` — виртуальное окружение Python (создаётся при установке, в git не хранится).

Пульт хранит в `~/.config/apitor-control/`: `addresses.json` (кэш адресов),
`config.json` (настройки), `runs.log` (журнал прогонов, если включён).
Программы и черновик `_draft.txt` лежат в папке `programs/` рядом со скриптом
(её можно хранить в git; раздел «Файлы программ»).
